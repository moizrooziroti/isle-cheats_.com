# Launch checklist (copy for submission)

Use this after **build + deploy** on your real URL (`isle-cheats.com` or Workers preview).

**Build commands**

| Target | Command |
|--------|---------|
| Production `https://isle-cheats.com` | `npm run build` (or `npm run build:prod`) then `npx wrangler deploy` |
| Workers staging (`*.workers.dev`) | `npm run build:workers` then deploy |

---

## 1. Build has no errors

**What the repo does:** `npm run` → `astro build` runs in CI/local; on success, `dist/` is generated.

**How to verify**

```bash
npm run build
```

Expect exit code **0** and `dist/` populated.

**Status for your submission:** Run the command above before each deploy; paste “Build succeeded (exit 0)” only after you see that locally or in CI logs.

---

## 2. No console errors or broken pages (desktop)

**What the repo does:** Static Astro output; internal links are checked by `npm run qa` (Linkinator crawl on local preview server).

**How to verify**

```bash
npm run build
npm run preview
```

In another terminal (with server running):

```bash
npm run qa
```

Or open DevTools → **Console** on homepage, `/products/`, one blog post, `/faq/`.

**Status for your submission:** Say “Verified after deploy” only after you’ve opened key pages and run `qa` or manual click-through.

---

## 3. Mobile: every page loads

**What the repo does:** Responsive layout (viewport meta, standard patterns). No separate mobile codebase.

**How to verify:** Chrome DevTools → **Toggle device toolbar** → test `/`, `/products/`, `/blog/`, `/faq/`, one product detail, one forum thread.

**Status for your submission:** Confirmed only by you on a real phone or device toolbar after deploy.

---

## 4. `sitemap.xml` and `robots.txt` live; sitemap lists indexable pages

**What the repo does**

- `dist/sitemap.xml` is generated by Astro + `scripts/finalize-sitemap.mjs`.
- `robots.txt` in `dist/` includes one `Sitemap:` line for the **same canonical origin** as the build (`PUBLIC_CANONICAL_ORIGIN` or Workers default).
- **Not every HTML file is in the sitemap by design:** e.g. **`/404/`** and **`/go/`** checkout redirects are excluded (see `@astrojs/sitemap` `filter` in `astro.config.mjs` and `src/config/sitemap.ts`). Legacy paths like `/cheats/` may exist as redirects; the hub is `/products/`.

**How to verify (replace with your live origin)**

```text
https://YOUR-DOMAIN/sitemap.xml
https://YOUR-DOMAIN/robots.txt
```

Expect HTTP **200**; sitemap valid XML with `http://www.sitemaps.org/schemas/sitemap/0.9` namespace.

**Status for your submission:** Paste your live `Sitemap:` URL from `robots.txt` and note: “All indexable routes included; 404 and /go/ excluded intentionally.”

---

## 5. Every page has its own `<title>`, meta description, and one `<h1>`

**What the repo does**

- **Title + description:** `BaseLayout` + `resolvePageSeo()` / product and blog data.
- **H1:** Each route uses a single primary H1 (hero, legal page, blog article, etc.).

**How to verify:** View source (not only Elements panel) on:

- `/`
- `/products/`
- `/products/the-isle-cheats/`
- `/blog/`
- one blog post
- `/faq/`, `/about/`, `/privacy-policy/`

**Status for your submission:** Spot-check 5–10 URLs after deploy.

---

## 6. Store / affiliate / checkout links open the correct product

**What the repo does:** Checkout uses internal paths `/go/.../` → server redirect to partner URLs (`src/config/checkout.ts`, `checkout-redirects.mjs`). Product cards map slug → `checkoutForSlug`.

**How to verify:** On each product page, click **Buy**; confirm redirect matches that product (main suite, HWID, Cloud DMA, UGC).

**Status for your submission:** Manual test of four product pages after deploy.

---

## 7. Images compressed and have alt text

**What the repo does**

- Build step `scripts/optimize-images.mjs` generates responsive **WebP/AVIF** from PNGs in image folders.
- Key UI images use `alt` (e.g. hero, blog hero, logo props).

**How to verify:** DevTools → **Network** → Img; Lighthouse “Properly size images” / “Alt text” (optional).

**Status for your submission:** Run Lighthouse on `/` and one blog post after deploy.

---

## 8. Copy is original — no placeholders

**What the repo does:** Content lives in `src/i18n/en.ts`, `src/data/blog/posts.ts`, `src/data/products.ts`, etc.

**How to verify:** Grep for `lorem`, `TODO`, `placeholder`, `coming soon` before launch; read legal and product pages for accuracy.

**Status for your submission:** Your editorial sign-off; automated grep optional.
